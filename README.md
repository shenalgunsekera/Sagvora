# Sagvora Innovations

The public site and content system for a business transformation company.

Near-black, two accents, condensed grotesque display type. Every animation is
hand-written — there is no animation library in the dependency tree. Every word
and every image on the public site is editable from `/admin`.

---

## Run it

```bash
npm install
npm run setup     # brand assets + database + seed content + imagery
npm run dev       # http://localhost:3000
```

`npm run setup` is safe to re-run: the seed only inserts rows that are missing,
so it never overwrites anything you have edited in the admin panel.

**Sign in at `/admin/login`**

| | |
|---|---|
| Email | `admin@sagvora.com` |
| Password | `sagvora2026` |

Change both from **Account** as soon as you are in, and change `AUTH_SECRET`

## The stack

| | |
|---|---|
| Framework | Next.js 15 (App Router, React 19, TypeScript) |
| Styling | Tailwind CSS v4 with a token layer in `globals.css` |
| Imagery | 13 dark editorial photographs in `public/imagery/`, ~55 KB each |
| Data | SQLite via `better-sqlite3` — a single file at `data/sagvora.db` |
| Auth | bcrypt password hash + signed JWT session cookie (`jose`) |
| Images | `sharp` — uploads are converted to WebP and capped at 2400px |
| Animation | none — see below |

No CMS to pay for, no external database, no third-party form service. The whole
site is one Node process and one file.

## Colour

Two accents, each with a job. They are never used as decoration.

| Token | Value | Means |
|---|---|---|
| `signal` | `#D9B978` warm gold | The brand mark — kickers, goals, section indices, active states |
| `cool` | `#A6C8E8` pastel blue | The machine — AI, agents, data, circuitry |
| `haze` | `#C9BDE8` pale lilac | Gradients only, to stop blends going flat. Never a flat fill |

Where the two appear together they read as **human vs. AI** without a legend:
the ladder's balance bar puts warm against cool, the hero lattice warms as
nodes take on energy, half the circuit pulses run cool, and stage-one glyphs
carry gold while the AI-stage glyphs carry blue. The scroll-progress bar runs
gold to blue across the page — the same journey the content makes.

Everything else is near-black and off-white. That restraint is what lets two
small accents carry meaning.

Handled, not left as a to-do:

| | |
|---|---|
| `og.png` | 1200×630 share card — the control-room photograph graded under the real logo lockup, with the gold-to-blue rule across the top. Generated by `npm run imagery`, so it never depends on a font being installed |

## The animation layer

`src/components/fx/` — all of it written for this site.

| File | What it does |
|---|---|
| `MotionRoot.tsx` | One IntersectionObserver, one rAF loop and one pointer listener for the whole document. Handles scroll reveals, the `--scroll` progress variable, and magnetic elements. Re-scans on route change. |
| `motion.ts` | Primitives: frame-rate-independent damping, smootherstep, viewport progress, text splitting. |
| `SplitText.tsx` | Splits text into masked units at render time — no flash of unsplit text, and the original string stays intact for screen readers and copy/paste. |
| `HeroField.tsx` | The canvas lattice. Nodes drift on their own, bend away from the pointer, and only draw connections where they have been energised. |
| `Cursor.tsx` | Dot pinned to the pointer, ring trailing behind it. Any element can change its shape or print a label via `data-cursor` / `data-cursor-label`. |
| `backdrops.tsx` | Three generated SVG backdrops — circuit traces with travelling pulses, a perspective grid, and topographic contour rings. Seeded PRNG, CSS-only animation, zero runtime JS. |
| `Preloader.tsx` | First-visit curtain, once per tab session. |
| `Glyph.tsx` | The capability line marks; each one animates a part of itself on card hover. |
| `Counter.tsx`, `Marquee.tsx`, `SheenCard.tsx`, `Grain.tsx` | Count-up, seamless loop, pointer-tracking light, film grain. |

Everything degrades under `prefers-reduced-motion`: content still arrives, it
just stops moving. The hero canvas stops its render loop entirely once it
scrolls out of view or the tab is hidden, rather than drawing frames nobody can
see.

Accessibility is handled rather than assumed: a skip link, a real pause control
on the testimonial rotator (hover alone is not a mechanism on a touch screen),
`aria-live` regions that exist before their message does, focus trapping and
Escape on the mobile menu, and `inert` on the closed overlay so it is not a
tab-order dead end. Every image declares intrinsic dimensions so nothing shifts
as photographs land.

### Using the motion system

```html
<!-- reveal on scroll: up | fade | blur | mask | scale | left | rule -->
<div data-reveal="up" style="--reveal-delay: 120ms">…</div>

<!-- pull toward the cursor; the number is the strength -->
<span class="magnetic" data-magnetic="0.3">…</span>

<!-- change the cursor over this element -->
<a data-cursor="view" data-cursor-label="Open">…</a>
```

## The admin panel

`/admin` — same visual language, higher density.

| Page | What it controls |
|---|---|
| **Dashboard** | Counts, unpublished warnings, latest enquiries |
| **Capabilities** | The cards and their detail pages — copy, features, at-a-glance figures, glyph, order, published state |
| **Work** | Case studies — client, metrics, the three chapters, cover, gallery, tags |
| **Ladder stages** | The five stages, including the human/AI split that drives the balance bar |
| **Testimonials** | Quotes for the Voices section |
| **Settings & copy** | Every line of text on the home page, the image band, contact details, headline numbers, social links, SEO |
| **Media** | Drag-and-drop upload; converted to WebP, capped at 2400px |
| **Inbox** | Contact form submissions — read, archive, reply |
| **Account** | Your email, name and password |

Public pages are `force-dynamic`, so a save is live on the next request. No
build step, no cache to purge.

Lists carry a search box and a Live/Draft filter (state lives in the URL, so a
filtered view is bookmarkable), and every ordered list has up/down arrows.
Reordering rewrites the whole list to sequential positions, which also repairs
duplicate or gapped `orderIndex` values left by editing the numbers by hand.

**Export JSON** on the dashboard downloads every editable record, drafts
included — diffable, greppable, and a viable migration path off SQLite.

### How authorization is enforced

Three independent layers, because the obvious single layer is not sufficient:

1. **Middleware** verifies the cookie signature on the edge. It cannot reach the
   database, so this is a filter, not proof of a live session.
2. **Every admin page** calls `requireAdmin()` as its first statement. This is
   the one that matters. A layout-only check is *not* enough: a layout and its
   page render concurrently and the response streams as it goes, so a
   `redirect()` in the layout sets a 307 while the page's payload — every value
   it queried — has already been written into the body. It looks fine in a
   browser and hands the whole page to anything reading the response directly.
3. **Server actions and route handlers** re-check independently, since neither
   passes through a page.

Sessions also carry a version number that is bumped on every password change, so
a reset signs out every other device. The sign-in form locks a caller out for
15 minutes after 8 failed attempts (in memory — move it into the database if you
ever run more than one Node process).

## Content that ships with it

The five stages and the position statement are yours, verbatim.

The **photography is generated placeholder imagery**, not photographs of real
Sagvora engagements — dark editorial scenes chosen to sit in the palette
(cool light, one warm highlight, deep shadow). One per capability, one per case
study, one for the image band. They are real files in `public/imagery/`, listed
in the media library, and swapping any of them is one picker in the admin.
Replace them with your own work as you get it; nothing else needs to change.

The **capabilities** and **case studies** are written to fit the model and are
ready to be edited rather than deleted. Case study clients are described by
sector rather than named, so nothing has to be retracted.

The **testimonials are seeded as drafts on purpose.** They are illustrative
examples, not real client quotes — leaving them unpublished means nothing
invented can reach the live site by accident. While no testimonial is
published, the Voices section is hidden from the home page entirely. Replace
them with approved quotes and publish.

## Before you launch

1. `AUTH_SECRET` in `.env.local` — replace with a long random string.
2. Change the admin email and password under **Account**.
3. Set `NEXT_PUBLIC_SITE_URL` to the real domain — the sitemap, canonicals and
   share tags all derive from it.
4. Replace the sample case studies and testimonials.
5. Put your real contact details and headline numbers in **Settings**.
6. Swap the placeholder photography for your own as it becomes available.

### Deploying

The site needs a **persistent filesystem** — `data/sagvora.db` and
`public/uploads/` both live on disk. A small VPS, a container with a mounted
volume, Railway, Render or Fly all work:

```bash
npm ci && npm run build && npm run setup && npm start
```

It will **not** work as-is on a serverless platform such as Vercel, where the
filesystem is ephemeral — the database would reset on every deploy. Moving to
Postgres or Turso would mean rewriting `src/lib/db.ts` and `src/lib/queries.ts`
only; nothing else touches the database.

**Back up `data/sagvora.db` and `public/uploads/`.** That pair is the entire
site's content.

```
scripts/seed.mjs           idempotent content seed
scripts/imagery.json       imagery manifest: source, alt text, what it attaches to

src/app/(site)/            the public site
src/app/admin/             the control room
src/app/api/contact/       the only public API route
src/app/sitemap.ts         sitemap built from published content
src/app/robots.ts          robots rules
src/lib/schema.sql         single source of truth for the database shape
src/lib/guard.ts           requireAdmin() — the page-level authorization gate
src/components/fx/         the animation layer
src/components/site/       page sections

```

The wordmark in the header is set live in Archivo with its width axis pulled in
to match the supplied logo, so it stays sharp at any size and inherits colour.
The raster originals remain at `/logo-light.png` and `/logo-dark.png`.
